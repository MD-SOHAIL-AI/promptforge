ForgeX runtime review and repairs — 18 October 2026

ForgeX is an Electron and Next.js embedded-development workspace backed by FastAPI, a durable AI agent, and PlatformIO. Its main task flow is request interpretation, staged generation, real compilation and repair, source evidence, independent requirement review, and publication of a reviewed result. Flashing is a separate hardware action. Provider authentication and a responsive UI establish only the beginning of that flow.

The review covered the current architecture and launch scripts, the earlier October incident reports, all 123 retained run records through read-only SQLite access, the active repair and verification paths, and the current test gates. The latest original run failed after a build was attempted before its source directory existed. Earlier runs also demonstrate inconsistent generated interfaces, unsuccessful compilation, bounded repair exhaustion and provider deadlines. These are distinct failure families; one passing test suite cannot establish that every generated project works.

The following runtime defects were reproduced or encountered during this review and repaired:

| Failure | Resulting behavior |
| --- | --- |
| Progress reset the stalled-turn count but retained an old reorientation turn. | Actual progress starts a new bounded recovery interval. Repeated unproductive work still stops after the existing limit. |
| A successful edit could checkpoint obsolete recovery counters before the turn settled. | A changed-file checkpoint clears obsolete stall, actionless-response and repair-without-build state immediately, retaining cumulative tool and time accounting. Save the current repair groups, build pairs, repair history and requirement evidence rather than restoring the initial checkpoint's values. A write that changes nothing retains the recovery state. |
| Oversized compiler guidance became an alphabetically sliced JSON preview that could omit the actual errors and instructions. | Shorten source previews as structured records while preserving compiler errors, freshness information, hashes and instructions. Omission markers remain explicit and the durable evidence is unchanged. |
| A valid PlatformIO configuration without a generated source directory surfaced as a generic project exception. | Report `LOCAL_SOURCES_INCOMPLETE` with the actual contained source directory and creation guidance. Preserve custom source layouts, retain the guidance through context compaction, and clear it after source creation. This does not engage the INI-only configuration barrier. |
| The main event loop owned the session heartbeat timer. A live replay lost its lease after an approximately 40-second scheduling gap. | Run the renewal timer and renewal operation in a background worker. Fence capabilities immediately on ownership loss, join the worker during cleanup, and preserve a lease-loss error when operation completion races the heartbeat. Expired or replaced ownership remains rejected. A full-process or machine suspension can still expire a lease. |
| Lease timestamps were captured before waiting for a write transaction. | Evaluate time after acquiring the transaction so a lock wait cannot issue an already-expired grant or revive an expired owner. |
| The replay generated a numeric pin macro and an equal private `uint8_t` constant with the same name. GCC then rejected the expanded declaration. | Add a narrow host repair requiring current compiler locations, a matching expansion note, equal literal values in the byte range, a private declaration, and contained non-hidden header paths. Remove only the redundant private declaration, retain the configured pin value, and rebuild. Public, differing, stale or outside-path cases remain unrepaired. |
