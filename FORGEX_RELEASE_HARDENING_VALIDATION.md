# ForgeX V4 Nexus — Final Release Hardening Validation

This document is the canonical validation record for the final hardened Agent Redesign package. Older `FORGEX_V3_VALIDATION.md`, `FORGEX_V4_VALIDATION.md`, and `FORGEX_AGENT_REDESIGN_VALIDATION.md` files are historical snapshots from earlier milestones.

## Security hardening completed

- Per-launch 256-bit desktop authentication secret generated by Electron.
- Secret stored in an HttpOnly, SameSite=Strict localhost cookie; it is not exposed through the renderer bridge.
- Backend desktop mode refuses to start without `FORGEX_LOCAL_TOKEN`.
- All HTTP API routes except `/health` require the authenticated local session when desktop auth is enabled.
- Loopback Host validation and local Origin validation are enforced for authenticated desktop requests.
- Execution and terminal WebSocket handshakes enforce the same local authentication boundary.
- Terminal HTTP routes are therefore blocked before shell creation unless the authenticated desktop session is present.
- Health response exposes only a short SHA-256 token fingerprint so Electron can reject a stale backend from another desktop session.
- External workspace file routes block sensitive credential paths such as `.env`, `.npmrc`, credential/token/private-key paths.
- External workspace traversal rejects symlinks and Windows reparse-point components.
- Agent model read/write boundaries reject high-confidence credential formats to reduce accidental secret exfiltration or insertion.
- Desktop release mode cannot disable the V2 orchestrator and silently fall back to split legacy action ownership.

## Release/compatibility hardening completed

- Canonical frontend API path is now `/api/forgex`; `/api/promptforge` remains a temporary compatibility alias.
- `FORGEX_API_URL`, `NEXT_PUBLIC_FORGEX_WS_URL`, and `NEXT_PUBLIC_FORGEX_BACKEND_PORT` are canonical; legacy PromptForge variables remain fallback aliases.
- WebSocket runtime uses the Electron-provided backend URL instead of hardcoding port 8000.
- Broken repository virtual environments no longer prevent fallback to a usable system Python; an explicit `FORGEX_PYTHON` override remains strict.
- Backend source fingerprint now includes Python source plus `requirements.txt`, `requirements.in`, optional `requirements.lock`, and `pyproject.toml`.
- Direct Python dependencies are exact-pinned in `requirements.txt`; `requirements.in` retains the source ranges for future lock regeneration.
- Backend runtime compatibility contract bumped to `forgex-agent-runtime-v3`.

## Environment-limited validation

A full `npm ci` / Next.js production build could not be completed in the review container because the package-registry restore timed out. The final ZIP intentionally contains no `node_modules`. Run these on the target Windows machine before signing a desktop release:

```bash
npm ci
npm run build:electron
npm run test:electron

cd frontend
npm ci
npm run typecheck
npm run lint
npm run build
```

Then run:

```bash
python -m pip install -r requirements.txt
pytest -q
```

## Deliberately not changed

The review's proposed xterm downgrade and `outputFileTracingRoot` change were not applied because no reproducible failure was established. Polling remains as a fallback behind SSE/WebSocket streaming for resilience.
